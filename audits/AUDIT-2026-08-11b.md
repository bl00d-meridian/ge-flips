# Integration audit — 2026-08-11b (walk-up context awareness, same-session)

Scope: the context-awareness change ruled today — dismissible/auto-minimizing walk-up
checklist, review-replaces-not-stacks, flat-book posture. Audited before calling the
build done; findings caught mid-walk were fixed in the same change. Numbering
continues from AUDIT-2026-08-11-reorg.md.

## Workflow walks

**Monitoring visit (flat book).** Boot lands on Home in flat posture: WHAT CHANGED
and vitals lead by construction (flex order, `[R21.5]`), the delta block opens with
the standing line "book flat since \<date\> — shadow book accruing, N trips closed
since", and the checklist auto-minimizes to a one-line summary because there is
nothing to walk through (`[R21.3]`). The NOW bar shows the idle line — it no longer
suggests "Walk-up · step 1" into a walkthrough that isn't rendering. Reading a
ticker, not skipping a workout.

**Active visit.** Open positions or standing quote legs (both count as an open
book), an armed rung, or a pending ruling keep the checklist expanded; the collapse
controls ("– this visit", "⌄ always") sit in the panel header, one tap each
(`[R21.1]`, `[R21.2]`). A ruling or fill arriving mid-visit re-expands an
auto-minimized checklist, because the condition is computed live.

**Review visit.** Review-due renders as one line in the walk-up panel ("weekly
review ready — N days of data") — never a second checklist. One tap (or opening the
Review tab while due) engages it: the visit's checklist becomes the review flow with
the walk-up's execution core absorbed as step zero while a book is live, the ready
line disappears, and the NOW bar follows the review's own steps (`[R21.4]`). Review
interaction stamps `lastReviewAt` as before. Engagement is keyed to the visit clock,
so a reload inside the same visit stays in review mode and the next visit reverts —
both by design.

## Findings

**F13 — the NOW bar could point into a hidden walkthrough (composition, caught
mid-walk, fixed).** `nextMove` suggested "Walk-up · step N" from the raw checklist
regardless of collapse state, and knew nothing about an engaged review — the exact
"two checklists demand attention" state the ruling forbids, one layer up. *Fix
shipped:* `nextMove` skips the checklist suggestion when the checklist isn't
rendering (dismissed / preference / auto-min) and follows an engaged review through
`ckEffectiveList` — the same list the renderer draws, so the two surfaces cannot
disagree (`[R21.3]`, `[R21.4]`).

**F14 — the review-ready line would have dodged the attention budget (metric
honesty, caught mid-walk, fixed).** A new standing decision point ("start review or
not") that doesn't count against the ≤7 budget is exactly the double-standard the
budget exists to prevent. *Fix shipped:* `walkupDecisionCount` counts it
(`[R21.6]`); the R13.1 probe fixture pins review-not-due so its exact-6 expectation
still measures what it always measured.

**F15 — probe-profile state leakage (verification infrastructure, fixed).** The
headless profile's localStorage persists across probe runs, so a prior run's review
engagement leaked into the next run's early assertions. In the app this persistence
is correct (same-visit reload keeps engagement); in the suite it's pollution — the
clean-fixture block now neutralizes all R21 state up front. Noted because the
failure mode ("test passes alone, fails after another run") will recur if future
per-visit state skips the fixture.

## Interpretations stated (not silently resolved) — both RATIFIED as built, Aug 11 2026

- **"Zero open positions" includes standing quote legs.** A standing quote is a
  working book — minimizing the walkthrough while a leg needs servicing would hide
  live guidance. `bookOpenCount` counts both; the same definition drives the flat
  clock. *Ratified with the reasoning made precedent: this is the F6 principle
  ("gp standing in an offer is deployed gp") reapplied to attention state — a
  working quote is an open book for the flat clock for the same reason it counts
  in `committed()`.*
- **Review trigger discrepancy.** The instruction said "5+ days of data per the
  existing trigger"; the existing trigger is **3** data days and a 3-day gap
  (`REVIEW_MIN_DAYS = 3`, `REVIEW_GAP_MS = 3d`). Per the definitions protocol the
  existing constants were kept and nothing was moved. *Ratified: 3+3 stands — "5
  days" was memory rounding, not a ruling; flag-rather-than-silently-follow was
  the correct handling either way.*
- **An engaged review ignores the standing minimize preference and the auto rule**
  (it was asked for this visit); a per-visit dismissal still collapses it.

## Orphan / redundancy scan

New state fields all have writers and readers: `visitStartAt` (rollVisit → per-visit
keys), `flatSince` (trackFlat → posture class + standing delta line), `ckPref` /
`ckDismissAt` (header controls → `ckMinimized`), `reviewEngagedAt` (ready-line tap /
Review-tab open → mode derivation, NOW bar). No duplicated checklist machinery:
`ckEffectiveList` is the single source for both the renderer and `nextMove`;
`document.querySelectorAll("ul.ck").length === 1` is probe-asserted in both engaged
and unengaged states.

## Attention accounting

The collapse controls add zero decisions (they're actions on the surface, not
choices demanded); the review-ready line adds one and is counted (`[R21.6]`);
cap 5 rulings + 1 reminder + 1 review-ready = 7 ≤ 7 — the budget still binds at the
construction level, probe-asserted.
