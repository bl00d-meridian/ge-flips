# Audit — 2026-08-11d (scoping regression: cause, why verification missed it, fixes)

Scope: the reported regression — Trade rendering RULINGS PENDING, WHAT CHANGED, and
the full walk-up block above its own content, despite item 2 of the interface ruling
being reported as shipped in `ede1b71` with a passing probe.

## The miss, explained (both halves)

**The defect (introduced in `959aee9`, two commits before the report that claimed
scoping shipped):** the flat-posture layout rule was written as
`#tab-home{display:flex;flex-direction:column}`. An ID selector outranks the
class-based tab gate `section.tab{display:none}`, so the Home section computed
`display:flex` on **every** tab from that commit onward. The scoping work in
`ede1b71` was applied to the correct render branch — the blocks live inside
`#tab-home`, and the JS dispatch was right — but the CSS gate that scoping depended
on had already been silently overridden.

**Why the probe passed (the ruled question):** the R22.2 assertions checked the
blocks' *existence* — `querySelector("#tab-home #homeRulingsPanel")` — which
succeeds whether or not CSS hides the element. Headless assertions never inspected
computed visibility, so a display-layer bug was structurally invisible to an
existence-based test. So: **not a wrong render branch — presence assertions where
only absence assertions can test a scoping rule.** The prior report's claim
("verified") was true of structure and false of the screen; this audit corrects it.

## Fixes

1. **CSS:** `#tab-home.on{display:flex;flex-direction:column}` — the flex layout
   now composes with the tab gate instead of overriding it. Ruled scoping restored:
   Home = digest + delta + checklist (+ global NOW/vitals); every other tab = NOW
   bar + vitals strip, then its own content immediately; ⚖ badge remains the only
   pending-rulings presence off-Home.
2. **Probe rewritten to assert the NEGATIVE** (`[R22.2]`): on Trade and Sleeve,
   none of the three blocks are visible (`offsetParent === null`,
   `getComputedStyle(#tab-home).display === "none"`); on Review, digest and delta
   are absent while the weekly checklist renders as that tab's own content; on
   Home, everything renders. **The detector was then proven against the original
   defect:** the bad selector was temporarily reintroduced and the suite failed
   with exactly the reported symptom (`{"home":"flex", dig:true, del:true,
   ck:true}`) before being restored to green. A detector that has never fired is
   unproven; this one has now fired once.
3. **Minimized checklist is ONE line** (`[R22.8]`): the panel header, section
   title, progress bar, and stacked attention line all fold in with the steps —
   only the summary row renders (title · steps done · reason · expand), with the
   attention reading moved into its tooltip. The attention *recording* still runs
   every walk-up render; only the stacked display line is gone. Genuinely active
   cues (elevated briefing reminder, review-ready line) still render — they are
   cues, not checklist chrome.

## Case law accreted

CLAUDE.md's Verification section now carries the ruling: scoping rules are tested
by absence — assert computed visibility on the surfaces that must be clean, and
prove new detectors against the original defect once. REQUIREMENTS R22.2 records
the regression and the re-verification inline.
