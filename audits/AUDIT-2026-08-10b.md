# Integration audit — 2026-08-10b (carry-over scope, on demand)

**Meta-finding (user, for the record):** F5 and F6 are money-path defects that 252
green assertions could not see — each subsystem passes its own tests, and only the
composition walk finds the seam between them. Parts-level verification and
composition-level audit are different detectors; a green suite is not a clean bill.

Scope: the two areas the first audit flagged unwalked — the deployment funnel's
internal stages and the inventory-quote cycle beyond its walk-up surface. Numbering
continues from AUDIT-2026-08-10.md. All findings are proposals; nothing applied.

## Findings (4)

**F5 — standing quote legs are invisible to the self-cross guard (missing edge,
concrete money path).** `crossWarn` reads `standingOrders` → `DB.positions` only. A
placed quote's legs live on the watch entry (`quotePlaced`), so: the sell-aging
ladder's "undercut & exit" reprice on a position can cross a standing quote BUY leg
at the bid, and a plan/margin-test leg can cross a standing quote SELL leg — no
CANCEL-FIRST warning either way. The quote card itself warns against positions
(`crossSell`/`crossBuy`), so the guard is one-directional: quotes see positions,
positions don't see quotes.
*Proposed:* `crossWarn` also consults `invItems()` with `quotePlaced` (unfilled
remainder > 0): sell proposals cross a standing quote buy at ≤ its bid; buy proposals
cross a standing quote sell at ≥ its ask. One function, both directions covered.

**F6 — the plan and the quote cycle both own inventory-mode items (redundancy /
double-commit).** `buildPlan`/`candidateFor` contain no reference to `invTarget`: an
inventory-mode item flows through the full gate chain and can be funded as an
allocator-sized plan BUY while the quote cycle simultaneously proposes its own buy
leg for the same item. Worse, `committed()` counts positions only — gp locked in a
standing quote buy leg is invisible to plan sizing, so the one-third rule and tier
pools can double-spend it. The walk-up then presents both steps ("place the plan's
buys", "quote inventory items") with no cross-reference.
*Proposed:* bench inventory-mode items from the plan with a stated reason
("inventory mode owns this item — its quote legs replace plan lines"), and count
unfilled `quotePlaced` buy legs (qty × bid) in `committed()`. Behavior change on
the capital path — needs your ruling, not just ratification of copy.

**F7 — `S.depProposalCount` is a stale sensor (composition).** It's computed only as
a side-effect of `renderDeploy` (Watchlist tab). The walk-up's RULINGS PENDING line
reads it from the Routine tab; between watch renders it reflects the last visit —
including the boot render, which runs before price data arrives and yields 0. A
funnel proposal earned overnight is silent until the user happens to render the
Watchlist.
*Proposed (cheap, honest):* stamp `S.depProposalAt` when set; the walk-up line
renders "as of the last Plan refresh, Nm ago" when stale, so the number states what
it measures. (Recomputing `buildPlan` on routine render is the expensive
alternative; not recommended — the stamp is enough.)

**F8 — the funnel swallows a negative residual (metric honesty, minor).** The
"live position / inventory" residual row renders only when
`N − stage kills − funded > 0`. A negative residual — which would mean a stage
double-counted a kill — is silently dropped, so the one number that could catch a
funnel accounting bug hides itself exactly when it fires.
*Proposed:* when residual < 0, render an explicit "accounting error: stages
over-count by N — funnel math needs a look" row. It should never appear; that's
what makes it a detector.

## Rulings (2026-08-10, all applied same session)

- **F5 ratified** — the guard reads every standing leg regardless of store, both
  directions. The user's finding on the finding: the original spec was universal
  ("whenever any reprice/undercut action is proposed… check for my standing
  opposite-side order"); the one-directional build was a dropped half-requirement —
  and the spec itself was never rowed in REQUIREMENTS.md, so the ledger detector
  had nothing to catch it with. Row **R9.4** closes both gaps; the previously-missing
  directions are the explicitly-probed ones.
- **F6 ratified, both halves** — (a) inv-mode items bench from the plan: one item,
  one mandate applies inside flipping too, not just between sleeves. (b) unfilled
  quote buy legs count in `committed()` at cost — correct even where it stings: gp
  standing in an offer is deployed gp; the one-third rule was lying by omission and
  now binds slightly earlier and honestly. Migration: free capital drops by the
  hidden legs on first load — not a regression, logged as "accounting corrected".
- **F7 ratified as proposed** — the timestamp over recompute. "As of Nm ago" is a
  true sentence; a fresh-looking stale number isn't.
- **F8 ratified** — an error detector wired to suppress errors; renders red when it
  fires.
