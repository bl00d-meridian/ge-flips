# Audit — 2026-08-13b: first runs of scans 10 and 11

Scans 10 (seam inventory) and 11 (information horizon) were specified in the graduation
commit and had never been run. **A scan specified but never run is a detector that has
never fired**, which is the thing the verification case law exists to distrust — so this
is their first run, on the precedent of scan 6, whose first run found four calendar paths
lifting a restraint the constitution said had exactly one.

**In both scans the enumeration is the deliverable.** What was checked and found clean is
recorded alongside what failed, so the next run starts from a list rather than from
scratch.

Probe suite re-run for the same reason: **PROBE-PASS, 906 assertions, 0 FAIL, 0 REQ FAIL,
PAIRING PASS** (257 tags claimed, 272 rows, 256 cited). `index.html` was not modified by
the graduation commit; the pairing check nonetheless reads `REQUIREMENTS.md` and was worth
re-running against the moved citations. Nothing moved that it could see — the scan

### S10-F1 — the contamination register and the cleanliness clock have no writer between them

**`paperCleanFrom()` reads `DB.paperDefectsClearedAt`. Nothing in the product ever writes
it.**

```js
function paperCleanFrom(){
  return paperDefectsOpen().length ? null : (DB.paperDefectsClearedAt || 0);
}
```

`PAPER_DEFECTS` is a **hardcoded source array** (`index.html:5872`); `paperDefectsOpen()`
slices it, and an entry leaves the register when a developer deletes it and ships a build.
`DB.paperDefectsClearedAt` is a **persisted runtime timestamp**. The two live in different
worlds and the field that joins them has a reader and no writer.

**Consequence.** Today the register is non-empty (`instant-trips`, `sell-credit`), so
`paperCleanFrom()` returns `null` and every trip reads contaminated — the safe direction,
which is why nothing has surfaced. **The defect fires the instant the last entry is struck
from the array:** `from` becomes `0`, `trips.filter(p => p.t >= 0)` matches everything, and
**every trip in the book — including every trip that closed while the defect was live — is
reclassified as clean evidence in one step, with no migration and nothing said on screen.**
It is the deployment direction (it widens what counts as evidence), it flatters the book,
and it is triggered by a build change rather than a user press.

The readers that inherit it are the ones that matter: `gapBandVerdict()` splits clean from
contaminated on this value, and the scanner proposal is HELD on `paperDefectsOpen()` — so
the same commit that clears the register both releases the hold and retroactively supplies
the clean evidence the hold was waiting for.

**This is the epoch-1 lesson inverted** (MISTAKES.md M097): *a corrupt population that
cannot be identified by a field must be discarded rather than partitioned*, and the answer
then was to stamp `FILL_MODEL_V`. Here the partition field exists in the reader and was
never given a writer.

**Proposed, not applied** — this is a verdict boundary and moves on a ruling:
persist the last-seen defect-id set, and at load, when the running build's `PAPER_DEFECTS`
no longer contains an id the store last saw open, stamp `DB.paperDefectsClearedAt = now`
(the migration precedent is `shadowPurgeV1` / `paperEpoch2Reset`). Clean then means "opened
after this user's app first ran a build without the defect", which is the sentence the
comment already claims. The alternative worth weighing: key cleanliness on `FILL_MODEL_V`
instead of a timestamp, since that field already partitions populations by the model that
produced them and needs no new state.

### S11-F1 — `reconReplay`'s causality guard cannot fire

```js
if (bt < p.t) continue;   // "a bucket that started before the trip did contains
                          //  prints from before it existed"
```

The caller clamps the window first:

```js
const from = p.lastObs || p.t;
const replayFrom = Math.max(from, oldest);
reconReplay(p, pts, replayFrom, now);
```

`from` is at minimum `p.t`, so `replayFrom >= p.t`, so every bucket reaching the guard
already satisfies it. **The guard is unreachable by its own upstream limits** — the dead
safeguard shape (MISTAKES.md M080, the 60-bucket trim behind a stored cap of 24).

Why it matters more than the trim did:

- It is the **only** line in the reconstruction path that states the causality rule, and it
  carries the comment asserting the rule is enforced there.
- **The Aug 12 instant-trip audit reasoned from it.** `AUDIT-2026-08-12-scope.md` §8 records
  `reconReplay` as having "causality (`bt < p.t` skips)" and rates it the least likely cause
  on that basis. That confidence rests on a line that cannot execute.
- It is untestable by construction: no fixture routed through `shadowRecover` can reach it,
  so any assertion written against it would be a dead seed.

**Proposed, not applied**, and the case law says to choose which layer owns the promise
rather than reflexively making the guard reachable: the promise is currently owned upstream
by the `Math.max` clamp. Either **delete the guard and assert the upstream guarantee**
(`replayFrom >= p.t` for every open trip), or **keep it and give it a fixture** that calls
`reconReplay` directly with a pre-open window. The first is cheaper and matches how the
dead calibration fallback was resolved; the second is right only if `reconReplay` is
expected to be callable from somewhere that does not clamp.

**A related note, recorded not raised:** the Aug 12 audit listed `reconReplay` as "the one
path where the minimum-life rule was never written". That gap is now closed in substance by
`bt !== p.buyDoneBkt`, which forces a round trip to span two distinct buckets — five
minutes — so no sub-second resolution is reachable there. Nothing said so when it landed;
it is said here.

## Result

**Five findings across two first runs**, none of them fixed: S10-F1 (a partition field with
a reader and no writer, which will silently reclassify the whole book the day the register
clears), S10-F2 (a BINDING reason composed and never rendered), S10-F3 / S10-F4 (write-only
residue), S11-F1 (a causality guard its own caller forbids from firing).

**Both scans found something on their first run**, which is the argument for running a scan
rather than shipping it. Both findings that matter are in the **deployment direction** —
one widens what counts as evidence, the other is protection that is not protecting — and
neither is visible from any screen.

Nothing applied. S10-F1 and S11-F1 both propose two options and recommend one; S10-F2 is a
one-line wiring fix that still needs a decision about where the sentence renders. Per the
standing rule, findings are ruled like everything else.
