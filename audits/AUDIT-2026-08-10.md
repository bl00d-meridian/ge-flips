# Integration audit — 2026-08-10 (first run)

Standing discipline per CLAUDE.md: workflow walks, orphan scan, redundancy scan.
Hunts unreported **composition** defects — probes cover parts, friction review covers
reported pain. Everything below is a **proposal**; nothing was applied. Findings are
numbered for ruling.

Scope walked this run: the four named workflows (walk-up, briefing cycle, sleeve
entry-to-exit, weekly review), all persisted DB keys, all Sleeve/Scanner/Watchlist
panels. Not walked: the deployment-funnel proposal engine's internal stages and the
inventory-mode quote cycle beyond their walk-up surfaces — next audit's first stop.

## Findings (4)

**F1 — `estWindow` is write-only (orphan, from today's build).** A ratified
`long-catalyst` stamps its calendar entry `estWindow: 1` (import and export→import both
preserve it), but no renderer reads it: an estimate-window catalyst card is
indistinguishable from a dated one, defeating the flag's purpose (the window is a
guess; entry-watch runway math presents it with dated confidence).
*Proposed:* calendar card renders an `est. window` badge and the runway line reads
"~Nd to window (estimate)" when `estWindow` is set. Small, display-only.

**F2 — flag-archive signature fields are write-only (orphan, from today's build).**
`flagArchive` stores `storyType`, `storyConf`, and `retracePct` per explained flag, but
`flagLagProfile()` reads only `peakToFlagD` — the lag note says "signature matches …"
while the stored signature beyond the lag is never consulted or shown.
*Proposed (either):* (a) enrich the lag note with the archive's dominant story class and
median retrace ("blog-driven runs here peak ~5d before the scan and retrace ~4%"), or
(b) stop storing the unread fields. (a) is the closed-loop intent; (b) is honest
minimalism. Ruling decides which.

**F3 — a ratified watch-note never reaches its flag's row (missing edge).** Watch-notes
are deliberately excluded from story-stamping (they record the *absence* of a story), so
after ratification the anomaly flag row still reads "2× no public story — watch-note
escalation due" — the escalation it asks for already happened, and nothing links the
flag to its watch-note record.
*Proposed:* flag row checks active watch-note records naming its item and renders
"escalated to watch-note (record id) — posture absence" instead of "escalation due".
Display-only; the noStory counter and export stay as they are.

**F4 — two daily-series caches over one endpoint (redundancy).** `dailyFor` (31-day,
mid-only, its own cache) and `slvDailyFor` (90-day, mid+volume, `slvDailyCache`, 20h
TTL) both poll `/timeseries?timestep=24h`. The split is documented as intentional, but
it means the cluster-coherence view and the entry watch can fetch the same item twice
in one sitting, and two cache invalidation stories exist for one data shape.
*Proposed:* one 90-day cache; `dailyFor` becomes a slicing read of it. Pure
consolidation, no behavior change intended; probe `[R2.1]`/`[R2.3]` must stay green.

## Checked, not findings

  validateImport still migrate old exports through it. Deliberate shim; retire only
  with an export-version floor. Concur: keep.
- **`beyond the net` slice feeds nothing** — by design (pure exploration, ruled); its
  "decision changed" is the manual +watch press. Not an orphan.
- **Four dismissal memories** (`rulingSnooze` 3d, `nudgeSnooze` per-day,
  `briefRemindDismissKey` per-occurrence, `audRuled` 7d) — four genuinely different
  clocks, each probe-covered. Name-similar, not concept-duplicate. Concur: keep.
- **`touchLog` vs `featTouch`** — attention denominator vs usage instrumentation;
  different readers, different retention. Not a duplicate.
- **`catalysts.items` + `catalysts.clusters`** — direct links vs basket links, merged
  by `catLinkedIds` at every read site. One concept, two storage paths, single reader —
  acceptable post-merge shape.
- **Workflow walks** — walk-up: every checklist step renders from live state with an
  inline section and a probe tag; briefing cycle: export → human → analyst → import →
  ratify → activate → entry-watch → ramp flag → export closes the loop (F3 is the one
  broken edge found); sleeve entry-to-exit and weekly review: every surface answered
  feeds/fed-by/earns-render (weekly's new attention step included).
- **Clusters-tab removal** — day-two orphan check the ruling predicted: the merged
  basket panels all have live writers and readers (probed `[R14.1]`/`[R14.2]`).

## Rulings (2026-08-10, all applied same session)

- **F1 ratified as proposed** — estimate windows now look like estimates everywhere
  they render: calendar card badge, entry-watch runway line ("~Nd … (estimate)"), and
  the briefing-cadence reminder.
- **F2 ratified as ENRICH, not drop** — the fields were collected to make signatures
  meaningful; the lag note now reads story class and median retrace ("mostly
  demand-context [confirmed] stories … median retrace −6% since peak"), not lag alone.
- **F3 ratified** — flag rows now link to their watch-note record with the absence
  posture. **For the record (user):** this is exactly the clusters-class defect
  (surface not wired to workflow), caught by audit in one day instead of by the user's
  irritation in four. The discipline works.
- **F4 ratified** — one 90-day cache; `dailyFor` is a slicing read of it, chart
  overlays read the shared cache via `dailyView`.
- **Cadence ruled:** weekly, tied to activity — run after any week containing a build
  session, skip after pure-usage weeks. Integration debt accrues at build speed.
  Written into CLAUDE.md.
